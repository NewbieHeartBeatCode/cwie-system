# ข้อกำหนดระบบ CWIE (System Spec)

ระบบสารสนเทศเพื่อการติดตามและการนิเทศงาน CWIE

เอกสารนี้สรุปขอบเขตระบบ บทบาทผู้ใช้ และฟังก์ชันหลัก อ้างอิงจากเอกสารออกแบบ `CWIE-System-Design-v4` (Google Doc) เป็นหลัก หากมีความขัดแย้งให้ยึดเอกสารออกแบบ และแจ้งผู้รับผิดชอบส่วน Docs เพื่ออัปเดต

---

## 1. บทบาทผู้ใช้งาน

| บทบาท (ในระบบ) | ชื่อที่ใช้ในเอกสารนี้ | ผู้ใช้จริง | หน้าที่หลัก |
|---|---|---|---|
| Student | นักศึกษา | นักศึกษาสหกิจ | ลงทะเบียน ยื่นสมัครสถานประกอบการ ส่งรายงานความก้าวหน้า ดูตารางนิเทศและผลประเมิน |
| Employer | สถานประกอบการ | ผู้ประกอบการหรือเจ้าของสถานประกอบการ | จัดการข้อมูลบริษัท ประกาศตำแหน่ง ตอบรับ/ปฏิเสธใบสมัคร กำหนดพี่เลี้ยง |
| Mentor | อาจารย์พี่เลี้ยง | พี่เลี้ยงหรือพนักงานที่ปรึกษาในสถานประกอบการ | ดูแลนักศึกษาระหว่างปฏิบัติงาน รับรองรายงาน ประเมินนักศึกษา |
| Advisor | อาจารย์นิเทศ | อาจารย์นิเทศ CWIE | ดูนักศึกษาในความดูแล นัดหมายและบันทึกการนิเทศ ประเมินนักศึกษา |
| Staff | Admin / เจ้าหน้าที่ CWIE | ผู้ดูแลระบบและเจ้าหน้าที่ส่วนงาน CWIE ของมหาวิทยาลัย | จัดการข้อมูลหลัก อนุมัติสถานประกอบการ มอบหมายอาจารย์นิเทศ ออกรายงานสรุป |

หมายเหตุ: ในโน้ตเดิมแยก "Admin" และ "ส่วนงาน/ผู้ดูแล CWIE ของมหาวิทยาลัย" เป็นคนละกลุ่ม แต่ในเอกสารออกแบบรวมเป็นบทบาท **Staff** บทบาทเดียว ดูหัวข้อ 5

ผู้ประกอบการและพี่เลี้ยงแยกกันเพราะเป็นคนละหน้าที่ (ผู้ประกอบการตัดสินใจรับนักศึกษา ส่วนพี่เลี้ยงดูแลงานประจำวันและประเมินผล) ในกิจการขนาดเล็กที่คนเดียวทำทั้งสองหน้าที่ ให้ผูกผู้ใช้คนเดียวกับทั้งสองบทบาทได้

## 2. โมดูลของระบบ

```
CWIE System
├── Login / Authentication                  → F-01
├── Role & Permission                       → 5 บทบาท (หัวข้อ 1)
├── จัดการข้อมูลผู้ใช้งาน                   → Staff จัดการผู้ใช้ทั้งระบบ
├── จัดการข้อมูลนักศึกษา                    → F-02
├── จัดการอาจารย์                           → Staff จัดการ advisors (ผ่าน users)
├── จัดการสถานประกอบการ                     → F-03
├── ระบบสมัคร/จับคู่/เข้าฝึก CWIE           → F-04, F-05, F-11, F-12
├── ระบบเอกสาร                              → ดูหัวข้อ 4 (ยังไม่อยู่ในเอกสารออกแบบ)
├── ระบบนิเทศ                               → F-06, F-07
├── ระบบประเมิน                             → F-09
├── ระบบติดตามสถานะ                         → F-08, F-10
└── Dashboard / รายงาน                      → F-10
```

### ฟังก์ชันหลัก (Must Have)

| รหัส | ฟังก์ชัน | รายละเอียด |
|---|---|---|
| F-01 | ระบบยืนยันตัวตน | เข้าสู่ระบบด้วยอีเมลและรหัสผ่าน ออกโทเคน แยกสิทธิ์ตามบทบาท |
| F-02 | จัดการข้อมูลนักศึกษา | เพิ่ม แก้ไข ค้นหา นำเข้าจากไฟล์ CSV กำหนดภาคการศึกษา |
| F-03 | จัดการสถานประกอบการ | ข้อมูลบริษัท ที่อยู่ พิกัด ผู้ติดต่อ จำนวนตำแหน่งที่รับ |
| F-04 | ยื่นสมัครและตอบรับ | นักศึกษาเลือกสถานประกอบการ ผู้ประกอบการตอบรับหรือปฏิเสธ Staff บันทึกผลการจับคู่ |
| F-05 | มอบหมายอาจารย์นิเทศ | ผูกอาจารย์กับนักศึกษา กำหนดจำนวนครั้งที่ต้องนิเทศ |
| F-06 | นัดหมายการนิเทศ | สร้างนัด เลือกวันเวลา รูปแบบ (ในสถานที่/ออนไลน์) แจ้งเตือน |
| F-07 | บันทึกผลการนิเทศ | บันทึกสรุป ปัญหาที่พบ ข้อเสนอแนะ แนบภาพถ่ายและไฟล์ |
| F-08 | รายงานความก้าวหน้า | นักศึกษาส่งรายสัปดาห์ พี่เลี้ยงรับรอง อาจารย์ให้ความเห็น |
| F-09 | แบบประเมินผล | สร้างแบบฟอร์มได้เอง ผู้ประเมิน 3 ฝ่าย (นักศึกษา พี่เลี้ยง อาจารย์นิเทศ) คำนวณคะแนนรวม |
| F-10 | แดชบอร์ดและรายงาน | สรุปสถานะรายภาคการศึกษา ส่งออกไฟล์ Excel และ PDF |
| F-11 | ประกาศตำแหน่งที่เปิดรับ | ผู้ประกอบการประกาศตำแหน่ง จำนวนที่รับ คุณสมบัติ ช่วงเวลาเปิดรับสมัคร |
| F-12 | กำหนดพี่เลี้ยง | ผู้ประกอบการเลือกพี่เลี้ยงให้นักศึกษาแต่ละคนที่บริษัทตอบรับแล้ว |

### ฟังก์ชันเสริม (Nice to Have)

ทำเมื่อ Must Have ครบทั้ง 12 ข้อแล้วเท่านั้น

- แจ้งเตือนผ่าน LINE Notify หรืออีเมล
- แผนที่แสดงตำแหน่งสถานประกอบการและวางแผนเส้นทางนิเทศ
- แชทระหว่างอาจารย์กับนักศึกษา
- Audit Log แบบละเอียด
- รองรับหลายภาษา

## 3. สิ่งที่แต่ละบทบาททำได้

**นักศึกษา (Student)**
- ดู/แก้ไขข้อมูลส่วนตัว
- ดูข้อมูลการฝึก CWIE ของตนเอง
- ยื่นสมัครสถานประกอบการ และดูสถานะใบสมัคร
- ส่งรายงานความก้าวหน้า และดูสถานะเอกสาร
- ดูข้อมูลสถานประกอบการ/สถานที่ฝึก
- กรอกแบบประเมินของตนเอง

**สถานประกอบการ (Employer)**
- จัดการข้อมูลสถานประกอบการของตนเอง
- ประกาศตำแหน่งที่เปิดรับ
- ตอบรับหรือปฏิเสธใบสมัคร
- กำหนดพี่เลี้ยงให้นักศึกษาที่ตอบรับแล้ว
- ดูข้อมูลนักศึกษาที่เข้าฝึกและเอกสารที่เกี่ยวข้อง
- ออกรายงานสรุปเฉพาะของบริษัทตน

**อาจารย์พี่เลี้ยง (Mentor)**
- ดูข้อมูลนักศึกษาที่อยู่ในการดูแล และข้อมูลการฝึก
- รับรองรายงานความก้าวหน้า
- กรอกแบบประเมินนักศึกษาฝั่งสถานประกอบการ
- ดูผลประเมินเฉพาะที่ตนเป็นผู้ประเมิน

**อาจารย์นิเทศ (Advisor)**
- ดูรายชื่อนักศึกษาที่รับผิดชอบ และข้อมูลการฝึก
- สร้างนัดหมายการนิเทศ และบันทึกผลการนิเทศ
- ดูเอกสารของนักศึกษา และให้ความเห็นรายงานความก้าวหน้า
- กรอกแบบประเมินนักศึกษา
- ดูผลประเมินและออกรายงานเฉพาะนักศึกษาที่ตนดูแล

**เจ้าหน้าที่ / Admin (Staff)**
- จัดการผู้ใช้ทั้งระบบ นักศึกษา อาจารย์ และสถานประกอบการ
- อนุมัติและตรวจสอบข้อมูลหรือเอกสารที่ส่งเข้าระบบ
- บันทึกผลการจับคู่ และมอบหมายอาจารย์นิเทศ
- สร้างนัดหมายการนิเทศ และสร้างแม่แบบแบบประเมิน
- ดูข้อมูลและผลประเมินทั้งหมด ออกรายงานสรุปทั้งระบบ

สิทธิ์ละเอียดทั้งหมดอยู่ในตาราง RBAC ของเอกสารออกแบบ (หัวข้อ 2.2) ใช้ตารางนั้นเป็นข้อกำหนดสำหรับ middleware ตรวจสิทธิ์

## 4. ระบบเอกสาร (ยังไม่อยู่ในเอกสารออกแบบ)

โน้ตกำหนดให้มีระบบกลางสำหรับเอกสาร โดยมีขั้นตอน:

**อัปโหลด → ตรวจสอบ → อนุมัติ → แก้ไข → ยืนยัน → เก็บประวัติ**

และแต่ละบทบาทเห็นเอกสารไม่เหมือนกันตามสิทธิ์

เอกสารออกแบบปัจจุบันมีเพียงตาราง `attachments` (ไฟล์แนบใช้ร่วมกัน) และ `notifications` ยังไม่มีสถานะการอนุมัติเอกสาร ประวัติการแก้ไข หรือการยืนยัน ต้องตัดสินใจก่อนลงมือทำ ดูหัวข้อ 5

---

## 5. จุดที่ต้องตัดสินใจ

1. **บทบาท Admin กับเจ้าหน้าที่มหาวิทยาลัย** โน้ตแยกเป็นสองกลุ่ม แต่เอกสารออกแบบรวมเป็น Staff บทบาทเดียว ควรเลือกว่าจะรวมหรือแยก ถ้าแยก ต้องเพิ่มบทบาทและปรับตาราง RBAC
2. **ระบบเอกสาร** ต้องเพิ่มตารางสถานะการอนุมัติ ประวัติการแก้ไข และการยืนยันเอกสาร ซึ่งยังไม่มีในตาราง `attachments`
3. **การจัดการอาจารย์** ในเอกสารออกแบบไม่มีหน้าจอแยก ใช้ตาราง `advisors` และ `users` ควรยืนยันว่าต้องการให้ Staff เพิ่มอาจารย์ได้เอง หรือรับจากระบบอื่น

## 6. ข้อมูลจริงจากภาควิชา CPE มทร. ศาลายา

สถานะ: **ยังไม่มีข้อมูลจริงในโปรเจกต์**

ข้อมูลที่ต้องการจากภาควิชาเพื่อใช้ทดสอบและ seed ฐานข้อมูล

- รายชื่อนักศึกษาสหกิจ (รหัส ชื่อ สาขา ภาคการศึกษา) สำหรับ F-02 และการนำเข้า CSV
- รายชื่ออาจารย์นิเทศ (คณะ ภาควิชา เบอร์โทร)
- รายชื่อสถานประกอบการที่เคยรับนักศึกษา (ชื่อ ที่อยู่ ผู้ติดต่อ)
- แบบประเมินที่ใช้จริงในปัจจุบัน สำหรับสร้างเป็น form template แรก

ข้อมูลเหล่านี้มีข้อมูลส่วนบุคคล ต้องไม่ commit ลง git ให้เก็บไว้ในเครื่องหรือ `backend/database/` ในรูปแบบที่ไม่อยู่ใน git และทำตามนโยบายความเป็นส่วนตัวของมหาวิทยาลัย
